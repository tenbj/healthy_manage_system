# 服务启停维护

> 适用于 `trading-ops-mvp` 本地开发、演示和 MySQL 联调环境。

---

## 1. 服务组成

| 服务 | 说明 | 启动脚本 | 默认端口 |
|------|------|----------|----------|
| API | Express 后端，提供运营台接口和数据存储适配 | `npm run dev:api` | `4310` |
| WEB | Vite + React 前端 | `npm run dev:web` | `5173` |
| 联合启动 | 同时启动 API 和 WEB | `npm run dev` | 由 `.env.local` 或默认值决定 |

当前项目已提供 `.env.local`，本机运行口径为：

```text
PORT=4410
DATA_STORE=memory
VITE_PORT=5273
VITE_API_PROXY=http://127.0.0.1:4410
VITE_API_BASE=http://127.0.0.1:4410/api
```

因此当前本机优先使用：

- 前端：`http://[::1]:5273`
- API 健康检查：`http://127.0.0.1:4410/api/health`

如果没有 `.env.local`，则回落到 README 默认口径：

- 前端：`http://127.0.0.1:5173`
- API 健康检查：`http://127.0.0.1:4310/api/health`

## 2. 首次启动

进入项目目录：

```powershell
cd E:\projects\健康餐减肥服务赋能\output\01_健康餐业务运营\03_代码程序\trading-ops-mvp
```

安装依赖：

```powershell
npm install
```

启动服务：

```powershell
npm run dev
```

看到 `API` 和 `WEB` 两组日志都持续运行后，再访问前端地址。

---

## 3. 健康检查

检查 API：

```powershell
Invoke-WebRequest -UseBasicParsing -Uri 'http://127.0.0.1:4410/api/health'
```

正常返回应包含：

```json
{"ok":true}
```

检查前端：

```powershell
Invoke-WebRequest -UseBasicParsing -Uri 'http://[::1]:5273'
```

如果使用默认端口，把上面两个命令中的端口改为 `4310` 和 `5173`。

## 4. 停止服务

### 4.1 前台运行时

如果服务是在当前 PowerShell 窗口中通过 `npm run dev` 启动的，按：

```text
Ctrl+C
```

确认终止后，API 和 WEB 会一起停止。

### 4.2 后台或窗口丢失时

先只查找本项目相关的 Node 进程：

```powershell
Get-CimInstance Win32_Process |
  Where-Object { $_.Name -eq 'node.exe' -and $_.CommandLine -like '*trading-ops-mvp*' } |
  Select-Object ProcessId, CommandLine
```

确认都是本项目进程后，再停止：

```powershell
Get-CimInstance Win32_Process |
  Where-Object { $_.Name -eq 'node.exe' -and $_.CommandLine -like '*trading-ops-mvp*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

不要直接批量杀掉所有 `node.exe`，同一台机器上可能还有 Codex、浏览器插件或其他项目的 Node 进程。

## 5. 重启流程

1. 停止本项目相关 Node 进程。
2. 回到项目目录。
3. 重新执行：

```powershell
npm run dev
```

4. 重新访问健康检查和前端地址。

## 6. 切换 MySQL 模式

默认 `DATA_STORE=memory`，适合演示和前端验证。需要联调 MySQL 时，在 `.env.local` 中使用：

```text
PORT=4410
DATA_STORE=mysql
VITE_PORT=5273
VITE_API_PROXY=http://127.0.0.1:4410
VITE_API_BASE=http://127.0.0.1:4410/api
DATABASE_URL=mysql://USER:PASSWORD@HOST:3306/healthy_meal_ops_mvp
MYSQL_SSL=false
```

口径说明：

- `DATABASE_URL` 由 `db_config.md` 中的 MySQL 资源临时组装，不要把真实密码提交到代码或文档。
- `MYSQL_SSL=false` 是当前本地联调口径；如果 RDS 安全策略要求 SSL，再改成 `true`。
- `DATA_STORE=mysql` 后，API 启动时会使用 MySQL 数据，不再使用内存种子数据。

初始化或刷新演示数据：

```powershell
npm run db:seed
```

只建库建表、不写入演示数据：

```powershell
npm run db:migrate
```

然后启动：

```powershell
npm run dev
```

## 7. 验收命令

服务变更、依赖变更或上线前，至少执行：

```powershell
npm run build
npm test
npm run lint
npm audit --audit-level=moderate
```

预期口径：

- `build`：TypeScript 和 Vite 构建通过。
- `test`：API 流程测试通过。
- `lint`：无 ESLint 错误。
- `audit`：无中高危依赖漏洞。

## 8. 常见问题

| 问题 | 判断方式 | 处理方式 |
|------|----------|----------|
| 前端打不开 | 查看 Vite 输出地址，可能是 `http://[::1]:5273` | 按终端实际地址访问，或在 `.env.local` 固定 `VITE_PORT` |
| API 404 或代理失败 | 检查 `VITE_API_PROXY` 和 `PORT` 是否一致 | 两者端口必须对应 |
| 页面提示请求失败 | 打开 `/api/health` 看 API 是否运行 | 先修 API，再刷新前端 |
| 端口被占用 | 查询本项目 Node 进程 | 停止旧进程或换端口 |
| MySQL 连接超时 | 检查 RDS 白名单、账号、密码、库名和网络 | 先用 `npm run db:migrate` 验证连接 |
| 日期读成前一天 | MySQL `DATE` 需要按本地日期读取 | 代码已在 `mysqlStore.ts` 使用本地年月日映射，不要改回 UTC 截取 |

## 9. 运维边界

- 当前是 MVP 开发服务，不是生产部署脚本。
- 暂未接入 PM2、Docker、Nginx、HTTPS 和正式 CI/CD。
- 生产上线前应补充最小权限数据库账号、RDS 自动备份、访问白名单、日志保留、异常告警和密码轮换。

# 原型图工具选择建议

> 日期：2026-06-07
> 类型：问题答疑 / 产品原型方法选择

---

## 问题

用户问：如果让 AI 画健康餐交易运营中台的原型图，会用什么工具？

---

## 简短回答

如果是这个项目，我不会只用传统“画图工具”。我会按目标分三层：

1. 用 Excalidraw 画业务流和模块关系草图。
2. 用 Figma 画少量关键页面的视觉和交互评审稿。
3. 真正推进产品时，直接用 HTML / React / Next.js 做可运行原型。

对这个健康餐交易运营中台，最有价值的不是静态图，而是能点、能录单、能看状态、能模拟收款核销和供应商下单的可运行原型。

---

## 我会怎么选

### 1. 最早期：Excalidraw

用途：

- 画客户、订单、收款、预付款、供应商履约之间的关系。
- 画运营流程：小红书线索 → 微信成交 → 系统建单 → 收款/预付款 → 供应商批次 → 配送 → 复购。
- 画页面之间的跳转关系。

为什么适合：

- 快。
- 不会被视觉细节拖慢。
- 适合讨论业务结构和模块边界。

不适合：

- 不适合沉淀最终 UI。
- 不适合验证真实操作效率。

### 2. 需要评审页面感觉：Figma

用途：

- 画运营中台关键页面的高保真稿。
- 评审信息密度、布局、视觉风格。
- 给非技术合伙人、运营、潜在团队成员讲清楚页面长什么样。

适合画的页面：

- 今日待办。
- 订单工作台。
- 客户详情。
- 收款与预付款核销。
- 供应商下单批次。
- 每日经营看板。

为什么适合：

- 视觉表达强。
- 原型演示方便。
- 适合多人评审。

不适合：

- 对你这种技术主导项目，Figma 不应该成为主要交付物。
- 如果业务规则还在变，维护大批 Figma 页面会很累。

### 3. 真正推进：HTML / React / Next.js 可运行原型

这是我最推荐给你的方式。

用途：

- 直接做一个能跑的运营中台原型。
- 可以录入客户、创建订单、模拟收款、核销预付款、生成供应商下单文本。
- 后续能自然演进成真实系统。

为什么适合你：

- 你是技术角色，不需要停留在“看起来像”的图。
- 这个业务的核心风险不是视觉，而是流程、状态和账务关系。
- 可运行原型能快速暴露真实问题：字段缺不缺、状态顺不顺、录单麻不麻烦、对账逻辑是否清楚。

我会优先做这种原型：

```text
Next.js / React 页面
静态 mock 数据
shadcn/ui 或 Ant Design 组件
不接真实数据库
先跑通关键交互
```

等流程确认后，再接后端和阿里云 MySQL。

---

## 我不会怎么做

### 不会一开始只画漂亮首页

这个系统不是 ToC 营销网站，第一屏不应该是大 hero 或宣传页。第一屏应该是运营每天打开就能干活的工作台。

### 不会一次画几十张页面

先画 5 个关键工作流即可：

- 录入客户。
- 创建订单。
- 记录收款。
- 预付款核销。
- 生成供应商下单批次。

### 不会把 Figma 当最终成果

Figma 可以帮助沟通，但不能验证账务流和订单状态流。对这个项目来说，交互原型比静态图更重要。

## 推荐原型路线

### 第 1 步：白板草图

工具：Excalidraw。

产物：

- 业务流程图。
- 模块关系图。
- 页面流转图。

目标：确认“系统到底管什么，不管什么”。

### 第 2 步：关键页面低保真

工具：Figma 或直接 HTML。

产物：

- 今日待办。
- 订单工作台。
- 客户详情。
- 收款核销。
- 供应商批次。
- 经营看板。

目标：确认信息架构和操作路径。

### 第 3 步：可运行交互原型

工具：Next.js / React。

产物：

- 能点的页面。
- mock 数据。
- 状态流转。
- 表单录入。
- 简单统计。
- 一键生成供应商下单文本。

目标：验证这个系统是否真的能让一个人处理更多订单。

### 第 4 步：接真实后端

工具：NestJS + 阿里云 MySQL。

产物：

- 数据库 schema。
- API。
- 登录权限。
- 真实 CRUD。
- 状态日志。
- 预付款流水。

目标：从原型进入 MVP。

## 对当前项目的推荐

如果你现在让我画，我会直接做：

```text
一个可运行的 Web 原型
```

优先页面：

1. 今日运营台：看今日待付款、待下单、待确认、异常。
2. 订单工作台：创建订单、改状态、看毛利。
3. 客户详情：客户资料、地址、忌口、历史订单、余额。
4. 收款核销：记录收款、关联订单、充值预付款、核销余额。
5. 供应商批次：按日期和供应商生成下单清单。
6. 经营看板：订单数、实收、营业额、预收款、毛利、异常。

这比单纯画几张图更接近你要的“技术为规模化赋能”。

---

## 工具选择结论

| 场景 | 我会用什么 |
|---|---|
| 讲清业务流程和模块关系 | Excalidraw |
| 和人讨论页面视觉 | Figma |
| 真正验证产品是否好用 | HTML / React / Next.js |
| 未来进入真实系统 | NestJS + 阿里云 MySQL |

最终建议：先用 Excalidraw 把业务流画清楚，但第一份真正有价值的原型应该是可运行的 React 原型，而不是静态图。

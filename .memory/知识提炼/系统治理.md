## 2026-06-07 · 主 agent 与 subagent 协作框架

**核心观点**：
- 多 agent 协作不应先追求“启动多少个 agent”，而应先建立任务卡、上下文包、交付包和验收报告四类契约。
- 主 agent 是唯一对用户目标负责的角色，负责需求澄清、任务拆解、调度、冲突处理和最终验收。
- subagent 是短周期执行单元，可以负责开发、测试、审查、文档和集成，但不能替代主 agent 宣告最终完成。
- 测试 subagent 应与开发 subagent 职责分离，目标是发现偏差，而不是证明开发正确。
- 质量门应分为分发前、合并前和最终验收三层，避免“执行完成”被误当成“目标完成”。

**关键框架/模型**：
- 角色模型：主 agent、开发 subagent、测试 subagent、审查 subagent、文档 subagent、集成 subagent。
- 任务对象：用户目标、任务图、任务卡、上下文包、交付包、验收报告。
- 生命周期：`INTAKE`、`PLANNING`、`READY`、`RUNNING`、`REVIEW`、`INTEGRATION`、`TESTING`、`ACCEPTANCE`、`DONE`、`REWORK`。
- 落地路线：文档化调度、半自动调度、自动化调度。

**与其他话题的关联**：
- → 健康餐业务运营：后续健康餐交易运营中台开发可以按该框架拆分开发、测试和验收任务。
- → 任务进度管理：真实执行时可用 B08 维护主 agent 调度状态和恢复入口。
- → 版本控制备份：subagent 修改 live 文件前仍必须遵守 B02 备份规则。
